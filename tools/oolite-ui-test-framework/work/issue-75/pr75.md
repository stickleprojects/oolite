Fixes #75 (mirror of upstream OoliteProject/oolite#793): the game window has no title bar on Ubuntu 26.04.

**Cause.** The AppImage does not bundle libdecor, so quick-sharun disables it by renaming SDL3's `libdecor-0.so` reference. GNOME 50 offers `fifo-v1`, so SDL3 uses native Wayland there, and GNOME expects Wayland apps to draw their own title bar, which SDL3 does with libdecor. On GNOME 46 (Ubuntu 24.04) SDL3 falls back to XWayland and GNOME draws the title bar, which is why it was not seen before. Full write-up and timeline on #75.

**Changes**
- `install_package_fn.sh`: install libdecor with the AppImage tools (`libdecor-0-0` on Debian/Ubuntu, `libdecor` on Fedora and Arch).
- `create_appimage_fn.sh`: `DEPLOY_SDL=1`, so quick-sharun bundles libdecor with SDL3 instead of disabling it.
- `install_packages_root.sh`: pin quick-sharun to `7cb538a0` instead of `main`, so the build uses the quick-sharun we tested.
- `LESSONS.md`: a row for this bug.

**Tested** (Ubuntu 26.04.1, GNOME 50.1, full `ubuntu-desktop` in a container, default Wayland session, 3 launches each):

| AppImage | Window frame | Title bar |
|---|---|---|
| 1.93.1-253 release | 1280×720 | none |
| This change, built on Arch (`oolite-builddeps`, the release path) | 1280×757 | yes (also checked by eye, headed) |
| This change, built in `ubuntu:26.04` (the Ubuntu CI job's image) | 1280×805 | yes |

Both fixed AppImages bundle `libdecor-0.so.0`, and `libSDL3` refers to it by its original name.

**Not tested:** the Fedora build path (quick-sharun does not support `/usr/lib64`; see upstream #777); GNOME 47 to 49; KDE and sway with this build; the rest of the CI job beyond packaging. The Ubuntu-built window is 48 px taller than the Arch-built one; not looked into.

Workaround for players on current releases: `SDL_VIDEODRIVER=x11`.
